# 中興大學校門口：需求與 SUMO 場景

本版本使用臺中市興大路 × 學府路的道路幾何。需求、車道與時制含明列假設，可用於整合測試。尚缺同址校門的轉向與行人觀測、相位秒數及獨立驗證時段，實際交通成效與模擬校準待完成。

## Phase 3：資料查核與輸入

2026-11-23 下載臺中市車輛偵測器設備位置 JSON，共 136 筆，檔案 SHA-256 為 `3b3d24446b4fcf536bc366e10e4263b336ad7f40262a6e2c5eb41ff451d4779c`。以 X 經度、Y 緯度對校門座標（24.1241218, 120.6751494）計算局部平面距離。最近三筆為 V450220（大明路，約 1.01 km）、V033260（大明路等，約 1.12 km）、V450550（大明路等，約 1.14 km）。這批設備無法直接給出校門各轉向。交通局南區調查清單有興大路及學府路其他路段，本次未取得校門四臂同時段的轉向與穿越數。資料缺口限於已查來源。[設備清單](https://data.gov.tw/dataset/84657) · [市府原始 JSON](https://newdatacenter.taichung.gov.tw/api/v1/no-auth/resource.download?rid=50d116d1-e787-4322-ab2f-ebbdfa1f8ef0) · [南區交通調查](https://www.traffic.taichung.gov.tw/form/index.asp?Parser=3,8,485,358,383,484,,289,,,1,,,,,h,0)

[需求資料與現場計數範本](../data/nchu/) 使用一份 CSV 表示一個 episode。每 900 秒一組，`arm` 是來源道路，`exit` 是去向道路：N 學府路、E 興大路東側、S 校門中興路、W 興大路西側。車種分 car 與 motorcycle。行人兩欄填同一臂，代表橫越該臂的合計人數。本版以單一穿越方向代表各臂總量。大型車、自行車與行人雙方向細分應另行留存原始調查，尚未建模。

現場或正式觀測資料須填 `basis=observed`、可追溯的來源編號／網址及整個 episode 的 `survey_start`（ISO 8601，含 +08:00）。由零起算的 `start` 為相對秒數。每區間共 28 列（12 個進出配對 × 2 車種，加 4 個行穿線），明確無通行填 0，未觀測留空。程式拒絕缺漏、重複、負數、混用來源或不連續區間；填完一組後可複製至下一區間並調整 start。可用相同輸入介面重播實測，來源真實性須回查原始紀錄。

三個 synthetic 情境每個均為兩個 15 分鐘區間。早、晚名稱表示模擬假設。第一個區間 N/E/S/W 每臂機動車分別設定為離峰 18/20/8/20、早峰 42/38/12/40、晚峰 25/42/34/45；第二區間每臂另加 4。各臂約一半直行、四分之一右轉，其餘左轉；每個轉向約三分之一為機車。早峰提高北側進口、晚峰提高校門出流。行人另按各臂設量。同一 seed 決定每個區間內的整秒出發時刻，總量固定。

## Phase 4：範圍、控制與執行

[道路折線](../sumo/nchu/geometry.csv) 保存原 OSM way、node 及經緯度，採局部公尺座標生成八條有向路段，中心節點為 13021816568。北接學府路與中興綠橋；南臂截於校門管制點；東西保留興大路曲線。每方向假設一條混合車道、30 km/h，各臂一條行穿線與兩側人行道，允許 12 個車輛轉向。車道容量、校門資格與閘門服務時間、轉向限制、停止線及行穿線精確位置待現勘。南臂短，未建模校內排隊與周邊路口的回堵。[OSM 來源及授權](data_sources.md)

netconvert 建立一個固定時制控制器。SUMO 1.24.0 生成 60 秒循環，兩組各 25 秒車行綠（其中最後 5 秒關閉行人綠）、3 秒黃、2 秒全紅。以上為初始假設。每個情境注入 1,800 秒，加 900 秒清空。Phase 5 使用動態控制前須重新驗證行人清空及每次轉相。

從專案根目錄執行，需可呼叫 netconvert、sumo 或 sumo-gui。

```bash
python scripts/nchu_demand.py data/nchu
python scripts/nchu_scenario.py data/nchu/morning_synthetic.csv --out results/nchu/morning
sumo-gui -c results/nchu/morning/gate.sumocfg
```

GUI 按播放即可觀看。其餘兩組使用相同指令，替換輸入與輸出目錄。若需逐筆驗收 GUI 可加 `--gui` 至 Python 執行入口。輸出含可獨立載入的 net、routes、sumocfg，另有逐程時間、行人軌跡、SUMO 統計與 JSON 摘要。CI 節點另打包三組場景。

## 初步檢查與校準狀態

下列為 SUMO 1.24.0、seed 42 的單次工程驗收。程式比對各車種與行人的輸入及完成數，從逐秒軌跡檢查每位行人實際經過指定行穿線。三組皆無碰撞、未完成或 teleport。

| 合成情境 | 小客車 | 機車 | 行人 | 車輛平均等待（秒） |
|---|---:|---:|---:|---:|
| 離峰 | 106 | 42 | 36 | 9.23 |
| 早峰 | 195 | 85 | 120 | 11.56 |
| 晚峰 | 213 | 95 | 112 | 10.77 |

下一次現地調查需同步記錄分向通過量、各行穿線人數、號誌切換時刻、校門放行條件，以及逐臂排隊數（含時刻與單位）。以第一組觀測設定轉向、容量與固定時制，再以獨立時段比較分臂排隊與等待，記錄對齊時段的誤差。現有平均等待值僅供重現合成場景，亦無法推論 RL 改善幅度。
