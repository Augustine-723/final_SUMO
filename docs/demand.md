# EI035 前期測試案例的分時交通需求

本頁資料用於驗證轉檔與品質檢查流程。正式研究路口為[臺中興大路 × 學府路](data_sources.md)。

原表為臺北市交工處 EI035（忠孝東路四段 × 光復南路）2025-06-12 的「調查」頁，原始網址及 SHA-256 見[來源清單](../data/metadata/site_sources.csv)。每個實測時段可重建 8 個連續 900 秒區間，四個進口共 32 筆進口區間。早晚合計 64 筆；各時段從模擬時間 0 秒開始。這批數字計量通過車流，重播為模擬需求時仍須檢查排隊、容量與未能進入路網的車輛。

## 重建

在專案根目錄，以已安裝 requirements.txt 的 Python 執行：

```bash
python scripts/process_demand.py
# 已下載官方原檔時
python scripts/process_demand.py --workbook /path/to/EI035.xlsx
```

預設自動下載清單指定的工作簿並檢查 SHA-256。可用 `--output` 指定輸出目錄。檔案校驗、時間結構、計數或官方小時加總不符時會停止並保留既有結果。

| 交付 | 用法 |
|---|---|
| [原表逐格 CSV](../data/processed/ei035_survey.csv) | 保留 D:BD 全部 3,392 個計數位置、原始表頭與儲存格地址。status 區分 positive、zero、blank；blank 的 count 留空。 |
| [情境需求 CSV](../data/processed/ei035_demand.csv) | 每列是一個情境、進口、15 分鐘、轉向及車種的觀測或合成輛數。保留明確零值，缺值不建立需求列；各情境均保留來源時段。 |
| [品質檢查](../data/processed/ei035_quality.json) | 原表格數、分時段計數及官方小時核對結果，可重新產生。 |

## 情境規格

| scenario | 來源與處理 | 兩小時機動車轉向計數，含另列兩段左轉 |
|---|---|---:|
| am_observed | 實測 07:00–09:00 | 18,300 |
| pm_observed | 實測 17:00–19:00 | 19,841 |
| offpeak_synthetic | 早峰每個進口區間縮至 50%，視為低需求假設 | 9,155 |
| directional_synthetic | 早峰東側 A 進口增至 150%，B/C/D 維持原值 | 20,826 |

合成倍率為專題設定。逐一進口、逐一區間將總量四捨五入，再按比例分配給已觀測的車種與轉向；剩餘整數優先分配給小數餘額較大的格子，同餘額按原欄序。數值固定，可另外用相同種子為各控制器生成區間內到達時刻。兩個合成情境共享早峰來源，不宜視為獨立觀測日或跨日泛化證據。

## 品質檢查與路線限制

- 以第 5–68 列的 15 分鐘計數重新加總，與同一工作簿「表」頁逐一比對 4 進口 × 4 小時 × 10 項；160 項相符。10 項涵蓋左、直、右各 3 類車種（大型車與公車依摘要合併），另加機車兩段左轉。這項檢查驗證轉檔與官方摘要一致。
- 一般左、直、右合計早峰 17,261、晚峰 18,870；另列機車兩段左轉 1,039、971。需求 CSV 保留 two_stage_left；Phase 4 需以一次旅程銜接兩段動作，避免將同一筆需求在兩個進口分別生成。自行車通過量早峰 247、晚峰 585，保留在逐格表；缺少分向轉向分配，未納入機動車情境總數。行人仍缺觀測。
- 原表 307 個明確零值、573 個正值及 2,512 個空格。D:P 是有機動車計數的欄組；Q:AX 在本次 64 列皆空白。可在逐格表辨識車道、車種與欄位缺漏。一般車道左轉公車欄有 16 個空白，小時加總只使用有數字的格子。
- 17:00–17:15 南側 B 進口的普通左轉有 **2 輛小型車**，與「基本」頁該時段禁左的記載有出入。觀測表與需求表保留兩輛。Phase 4 的合法路線重播應分列這兩輛為未映射需求，並輸出排除數；不得將其悄悄分配至直行或放寬相位。東、西側禁左有大客車例外；原表另有大型車左轉，車種欄位無法逐車確認是否符合例外。也應在路線映射時保留此不確定性。
